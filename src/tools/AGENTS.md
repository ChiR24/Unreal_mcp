# src/tools

Tool contracts and routing for the 23 **internal canonical parent tools** (not the default public listing). The gateway surface hides these parents behind a single `unreal` tool; their contracts live in capability records, not hand-maintained definitions. Orchestration selects a domain handler; handlers validate and send bridge requests to Unreal.

## STRUCTURE
```
tools/
|-- catalog/
|   |-- consolidated-tool-definitions.ts  # generated facade over canonical records (read-only)
|   |-- capabilities/
|   |   |-- model.ts                 # CapabilityRecord / ParentToolMetadata types (contract types)
|   |   |-- records/                 # CANONICAL CONTRACT SOURCE: per_tool/<tool>/ records + parent-metadata.ts
|   |   `-- generated/               # generated parent-tool-definitions + canonical-registry (do not hand-edit)
|-- definitions/shared/              # ONLY 2 files: tool-definition.ts, action-sets.ts (consumed, not edited)
|-- dynamic/                         # enable/disable state by parent tool and category
|-- orchestration/
|   |-- consolidated-handler-registration.ts  # registerDefaultHandlers(): all toolRegistry.register() calls
|   |-- consolidated-routing.ts      # action-to-domain routing sets
|   |-- consolidated-handler-dispatcher.ts    # call normalization, registry resolve, context
|   |-- consolidated-call-utils.ts   # dispatch helpers
|   `-- consolidated-tool-handlers.ts         # bootstrap/export facade (no routing logic)
|-- handlers/                        # domain action implementations; see nested AGENTS
|-- schemas/                         # legacy/shared core schema fragments
|-- editor/                          # editor facade modules
|-- environment/                     # environment facade tests/support
`-- level/                           # level facade and operations
```

## WHERE TO LOOK
| Task | Location | Notes |
|------|----------|-------|
| Change a tool contract (name/category/actions/schemas) | `catalog/capabilities/records/<tool>/` + `records/parent-metadata.ts` | `CapabilityRecord` entries are the **sole contract source**. `parent-metadata.ts` holds the canonical parent metadata (name, category, description, protected flag). Edit records, never the generated outputs. |
| Inspect the aggregate parent list | `catalog/consolidated-tool-definitions.ts` | Generated facade over canonical records. Read-only; regenerated by `npm run registry:generate`. |
| Regenerate / verify generated facades | `scripts/generate-canonical-registry.ts` (`registry:generate`, `registry:check`) | Emits `catalog/capabilities/generated/*`, `orchestration/generated-routing-index.generated.ts`, and native aggregator/shards. `registry:check` fails (exit 1) if any generated target drifts. |
| Register parent handlers | `orchestration/consolidated-handler-registration.ts` | `registerDefaultHandlers()` owns all 23 `toolRegistry.register()` calls. |
| Change action-to-domain routing | `orchestration/consolidated-routing.ts` + `orchestration/generated-routing-index.generated.ts` | Hand-authored routing sets plus the generated index derived from records. |
| Change call dispatch/errors | `orchestration/consolidated-handler-dispatcher.ts`, `consolidated-call-utils.ts` | Normalize call, resolve registry handler, preserve tool/action context. |
| Bootstrap/export orchestration | `orchestration/consolidated-tool-handlers.ts` | Side-effect registration plus public exports; no routing logic. |
| Enable/disable tools | `dynamic/` | Categories: `core`, `world`, `gameplay`, `utility`, `all`. |
| Implement an action | `handlers/<domain>/` | Follow `handlers/AGENTS.md`. |

## CANONICAL SURFACE (23 internal parents)
- Core: `manage_tools`, `manage_asset`, `manage_blueprint`, `control_actor`, `control_editor`, `manage_level`, `system_control`, `inspect`.
- World: `build_environment`, `manage_geometry`, `manage_pcg`, `manage_level_structure`.
- Gameplay: `animation_physics`, `manage_effect`, `manage_gas`, `manage_character`, `manage_combat`, `manage_ai`, `manage_inventory`, `manage_interaction`.
- Utility: `manage_sequence`, `manage_audio`, `manage_networking`.

These are internal. The public surface is the single `unreal` gateway tool (`search`/`describe`/`execute`/`configure`); the 23 parents are reachable only through it.

## CONVENTIONS
- Capability records are the single source of truth. A parent's name, category, description, action set, and input/output schemas all derive from its `CapabilityRecord` entries and `parent-metadata.ts`. There is no separate hand-maintained `all-tool-definitions.ts` or category parent-definition file to edit.
- `catalog/consolidated-tool-definitions.ts` and everything under `catalog/capabilities/generated/` are generated outputs. Never hand-edit them; run `npm run registry:generate` to regenerate after changing records, and run `npm run registry:check` before submission to verify no generated target has drifted.
- A new parent requires: capability records under `records/<tool>/`, an entry in `records/parent-metadata.ts`, and a matching `toolRegistry.register()` in `consolidated-handler-registration.ts`. The generated facades and native registration follow automatically from the records.
- Keep action strings aligned across capability records, routing predicates, handler switches, C++ bridge registration, native MCP schema, and tests.
- `manage_tools` and `inspect` are protected; preserve local TS dynamic-tool behavior and native parity.
- Keep output schemas schema-backed. Use `unknown`, narrow at boundaries, and preserve structured error context.

## ANTI-PATTERNS
- Editing `catalog/consolidated-tool-definitions.ts` or any `generated/` file by hand instead of the source records.
- Adding routing logic to the `consolidated-tool-handlers.ts` bootstrap facade.
- Calling domain handlers outside the registry/`handleConsolidatedToolCall()` path.
- Adding schema-only actions without TS handling, C++ handling, and targeted tests.
- Sending paths or console commands around shared validation, or writing runtime `console.log` output.

## OWNERSHIP
- `src/server/AGENTS.md` owns MCP SDK list/call registration and the local `manage_tools` intercept.
- `handlers/AGENTS.md` owns handler signatures, normalization, dispatch, and tests.
- `src/tools/catalog/capabilities/` owns the canonical contract records and their generated facades; `scripts/generate-canonical-registry.ts` owns regeneration and drift detection.
