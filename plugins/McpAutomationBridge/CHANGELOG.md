# Changelog

All notable changes to the MCP Automation Bridge plugin will be documented in this file.

---

## [Unreleased]

### Added
- **`control_actor.sample_motion`** — `HandleControlActorSampleMotion` samples an actor's location, `GetVelocity` and `propertyNames` (also `Component.Property`) from an `FTSTicker` on game time every `intervalSeconds` (default 0.05, 0 = every frame) and replies on game-time `durationSeconds` (default 2, 0.05-30 s), the 400-sample cap, `maxRealSeconds` (default 25, clamped 1-50), `startWhenTimeout` or loss of the actor or world (`endedBecause`); a world that is not PIE/Game is `NOT_SIMULATING`. `inputs` (max 32; `atSeconds`, `holdSeconds` default 0.1) press and release keys through `SimulateEditorInputForMcp` on game time, never in the frame they went down, and release any still down at the end (`inputsApplied`); keys pressed on a player-controlled pawn that then moved 1 unit or less add a warning that a menu or locked input probably swallowed them. `startWhen` {`actorName`, `propertyName`, `equals`, `waitForChange` default true, `maxWaitSeconds` default 10, max 30} holds the run until the value becomes `equals` (by JSON type; `waitedSeconds`); a timeout carries `McpStartWhenTimeoutWarning` (last value, `waitForChange: false` hint). The run holds the editor through `BeginEditorRunForMcp`/`EndEditorRunForMcp`: it restores a minimized main frame with `RestoreWindowForCaptureForMcp` (no activation; `windowRestored`) and clears `bThrottleCPUWhenNotForeground` in memory (never saved), and every end of the run (the ticker's end or the subsystem gone) minimizes the frame again with `MinimizeWindowForMcp` and puts the preference back. It counts frames: `McpSlowFrameWarning` fires at 0.1 game-s or more per frame. Replies `samples` (`t`, `location`, `velocity`, `properties`), `start`, `end`, `min`, `max`, `sampleCount`, `gameSeconds`, `realSeconds`, `missingProperties`.
- **`configure_editor` `window` minimizes** — `HandleControlEditorRestoreWindow` reads `minimize` and runs `MinimizeWindowForMcp` (a window placement with `SW_SHOWMINNOACTIVE` on Windows, `SWindow::Minimize()` elsewhere; no activation) instead of the restore, turns `bThrottleCPUWhenNotForeground` back on and saves it (`unthrottle` is ignored), and replies `wasMinimized`, `minimized` (read back from the native window), `restored` and `throttleOff`. A restore's `unthrottle` clears the preference in memory only (no `SaveConfig`). `-McpStartMinimized` on the command line arms a core ticker in `UMcpAutomationBridgeSubsystem::Initialize` that runs `MinimizeWindowForMcp` on the root window once it is visible (the main frame is added hidden and `FMainFrameHandler::ShowMainFrameWindow` shows it maximized at the end of startup), keeps it minimized for 10 s after, and gives up after 600 s.
- **Fab imports in the background** — the Fab adapter answers an add when Fab accepts the download. `McpFabImportOperations` keeps one record per add (the last 16) with a first-in-first-out queue of 8; `McpFabImportWatcher` ends each import (6 s of quiet with Interchange idle, at most 300 s of waiting on it, a ceiling of 600 s plus 1 s per MB, `GIsRunningUnattendedScript` held meanwhile) and `McpFabLogCapture` fails it early on a scrubbed `LogFab` error. `get_fab_import_status` reads the store and never the page. `McpFabDownloadProgress` reads the percent from Fab's "Downloading <name>" notification and, for `cancel_fab_import`, presses its Cancel button (`SimulateClick`, packs only); `McpFabInterchange` switches mesh combining off on the pipelines Fab generated (`combineMeshes: false`) and cancels a translation through `GetInterchangeManagerScripted` and `CancelAllTasks`, by reflection. `McpFabPostImport` saves what the import left dirty through `McpSafeAssetSave` once it settles, and `SaveAgain` does it again 15 and 60 seconds later (`McpFabImportOperations::Amend` stores each result) for what Interchange marks late; the status read says `NOT SAVED` in its message and `note`.
- **Fab relocation and naming** — `McpFabRelocate` moves what an import created in its own folders under `/Game/Fab` to `destinationPath` and names the mesh or surface (`assetName`): `RenameWithSettingsFollow`, `FixupRedirectorsIn`, then `McpSafeDeleteFolder` for the folders left empty. The shared `/Game/Fab/Materials`, `MaterialFunctions` and `Textures` never move, a taken target stops it before anything is renamed, and a cancelled import is not touched.
- **Fab page scripts** — `McpFabSelectionScript` (engine-build pick, tier pick, file size, one scene-size threshold) and `McpFabListingScript` (publisher, category, rating, license, price) are interpolated into the add, the details and the search, so they cannot disagree; `listingFacts` derives `isCc0` (`/\bCC-?0\b|public domain/i`) and `attributionRequired` (`/\bCC[- ]?BY\b|creative commons attribution/i`) from the license names, never from Fab's per-license `isCc0`, which a CC-BY license carries too, and the details handler passes `attributionRequired` on; `McpFabBridgeDispatch` waits for a page that is not ready (15 s page budget, 60 s slot budget) instead of answering `PAGE_NAVIGATING`. The provider's plain data structs moved to `McpFabTypes.h`, and the search takes one `FMcpFabSearchRequest`.
- **Fab library sync** — `HandleListFabLibrary` runs Fab's own `Fab.TEDS.MyFolderIntegration` (one fixed command and page size, through the registered console object) when the table has no rows, and answers from the core ticker once the row count has held still for 1.5 s or 12 s have passed; the query it registers is now released on every path.
- **`control_actor.list` filters** — `near` ({x,y,z} or array) with `radius` (without `near`, or negative: `INVALID_ARGUMENT`) filters by distance to the actor's world bounds (0 inside) and sorts nearest first (ties: smaller bounds half-diagonal, then path) with a per-row `distance`; `tag`, `className` (class or any parent, by name or path, `_C` optional) and `folder` (that outliner folder or below, `"(none)"` = root) filter before counting and paging (`McpActorMatchesListFilters`); `propertyNames` reads `Component.Property`. The handler moved to `ControlActor/List/McpAutomationBridge_ControlActorList.cpp`.
- **`control_actor` actions** — `set_transform` takes `offset` [x,y,z] added to the current location (refused with `location`; also per item in `actors[]`); new `rename` sets the label (`SetActorLabel`, `INVALID_NAME`) and, with `renameObject`, the sanitized, unique object name (an actor in an external package keeps its object name and the reply carries a `note`); `spawn_batch` reports an item without `actorName` by `GetName()` and lists those names in `unnamedActors`, whatever `report` filters; `set_visibility` and `set_actor_collision` take `actorNames` through `McpResolveActorNames` (also `add_tag`'s list: `McpHandlerUtils::GetStringArrayField`, `FindActorByName` per name, actors once each), the names that matched none in `missing` (`ACTOR_NOT_FOUND` with them when none matched), both under one `FMcpScopedEditorTransaction` ("Set Actor Visibility", "Set Actor Collision") over every actor and primitive component, with the `undo` block in the reply (`VISIBILITY_MISMATCH` names the actors that did not read back); `set_material` opens a "Set Actor Material" one the same way (`McpAddActorUndoSet` over the actor, after settling which components take the slot so a no-op opens none; the `actorNames` form holds one over every actor that resolves and each actor's captured run, like `spawn_batch`'s material, leaves its own to the caller: `FMcpResponseCaptureRegistry::IsCapturing`), both naming the actors they changed in `affectedActors` (each `McpActorRef`, the ones that read back as asked, or that had a primitive component updated; `updatedActors` counts that list) for the receipt's `changes` and `handles` (both doors' extractors read the array, `extractHandles` and `McpExtractReceiptHandles` deriving one actor handle per entry: the first 20 entries, deduped against the single-actor handle; `add_tag`'s many form lists every actor it resolved and tagged the same way, `taggedCount` counting them, and `set_material` with `actorNames` lists each actor whose one-actor run applied, once, by the name that run replied with; so do the `spawn_batch` reply (every actor that spawned, whatever `report` keeps), the `set_transform` `actors[]` reply (each actor that moved, `McpActorRef`, once, in the re-check pass) and the `set_blueprint_variables` `actors[]` reply (an actor that took a variable), whose single form answers `actorName` when it applied one), `set_actor_collision` reporting `componentsUpdated` and the actors without a primitive component in `noPrimitiveComponents` (`NO_COMPONENT` when none had one).
- **Coplanar report and `fix_coplanar`** — `McpCoplanar::FindCoplanarFaces` measures how much of each local-bounds face a static mesh fills (LOD0 triangles, >= 0.5 counts), builds world faces for every visible non-instanced static mesh component and sweeps them along X (0.5 unit plane tolerance, > 1 unit overlap); `audit_placement` merges hits per actor (`kind: coplanar`, `coplanarFaces[]`) and takes `kinds`. New `fix_coplanar` (`nameFilter`, `distance` default 1 clamped 0.1-20, `dryRun`) shifts one face of each pair (forward when the overlap covers >= 95% of the face, else back), resizes a lone `StaticMeshActor` whose two faces on an axis both move, and repeats up to 4 passes (1 for `dryRun`) in one transaction; two parts of one Blueprint actor are separated by moving the template component (`FixCoplanarInsideBlueprints`, planned before any compile; skipped when a placed copy overrides the location). Replies `pairsFound`, `actorsMoved`, `remainingPairs`, `passes`, `moved[]`, `blueprintsFixed[]`, `skipped[]`. The tilt check moved to `Placement/PlacementTilt.cpp`.
- **`componentNames` filter** — `control_actor.get_components`, Blueprint `get_components` and `inspect_cdo` keep rows whose `name` matches (case-insensitive) and return the rest as `missingComponents` (`FilterRowsByListedNames`). World-actor rows also carry `staticMesh` and `materials` through `McpHandlerUtils::AddMeshAssetFields`, which the Blueprint inspection now shares.
- **Runtime roles** — `ResolveObjectFromPath` resolves `GameInstance`, `GameMode`, `GameState`, `PlayerController`, `PlayerPawn`, `PlayerState` and `HUD` (case-insensitive) from `GEditor->PlayWorld` after the actor name/label lookup, and `FindActorByName` answers a PIE miss with the exported `ResolveRuntimeRole`, so every `control_actor` action takes them; get/set property share one not-found message that names them. A live PIE `UUserWidget` resolves by object or Widget Blueprint name.
- **`get_scs` component-class scan** — `path` (a folder) and `componentClass` (name part or /Script path, matched on the class or any parent) list the Blueprints under the folder, sorted by package, with a matching own or inherited component, opening at most 300 (`blueprintCount`, `scanned`, `truncated`); `componentClass` also filters one Blueprint's listing. `inheritedComponents` now includes parent Blueprints' SCS components (`ownerClass` is the owning Blueprint), not only the native parent's.
- **Blueprint graph** — `delete_node` takes `nodeIds[]` (or `nodeId`/`nodeGuid`): every id must resolve (`NODE_NOT_FOUND`) and pass `CanUserDeleteNode` (`PROTECTED_NODE`) before any is removed, then one transaction and one save; `set_pin_default_value` on a pin whose default is ignored feeds it a `UKismetSystemLibrary::MakeLiteral*` node (`FeedReadOnlyPinLiteral`; structs, enum bytes and containers stay `PIN_REQUIRES_CONNECTION`; a rejected value removes the node it made); Blueprint `get` with `Component.Property` reads the component template default (SCS node, else the CDO's default subobject, else the object held by that property), and its `PROPERTY_NOT_FOUND` lists the Blueprint-visible variables (`McpBlueprintVariableList`, shared with `set_blueprint_variables`); `rename_variable` renames a component when no variable matches (`FKismetNameValidator`, `NAME_CONFLICT`; reply `kind` is `component` or `variable`).
- **`arrange_nodes`** — `ArrangeNodes` (in the delete-nodes file, both take `nodeIds`) parks the listed nodes out of the way, runs `SettleAutoPlacedNodes` on them (now returning the nodes that did not move) and restores those; replies `moved` (`nodeId`, `nodeTitle`, `x`, `y`) and `unmoved`, under one transaction.
- **`set_property` `watch`** — `McpPropertyWatch::ParseWatch` resolves the watched object (`ResolveObjectFromPath`, `McpSafeReflectionTarget::IsAddressable`) and property before the write; `SendAfterWatch` samples it on the core ticker for `durationSeconds` real seconds (default 0.5, at most 20; `intervalSeconds` default every frame), keeps a sample when the exported value changed (at most 400) and adds `watch` (`samples` {`t`, `value`}, `sampleCount`, `changed`, `frames`) to the reply. A write of an actor transform or `bHidden`, which is set directly, refuses a watch.
- **`build_graph` member steps** — `add_function` (`functionName`, `inputs`, `outputs`, `pure`, `isPublic`; `$id` is its entry node, `$id_return` its return node), `add_event` and the new `add_event_dispatcher` (`dispatcherName`, `parameters`) run in the batch before the nodes that use them, and their names count as declared for the pre-check. `create_node` takes `CallDelegate` (a dispatcher), `Message` (an interface function) and `AsyncTask` (a task or async-action factory, event graphs only), resolving calls on the skeleton class so members added earlier in the batch are found before any compile. `add_function` reads `pure` (its call nodes have no exec pins) and replies `nodeGuid`/`resultNodeGuid`; `add_event` reports the event node's guid, not a call node's.
- **`get_node_details` `followExec`** — `McpExecChain` walks exec outputs (`PC_Exec`) depth-first from the node, each node once, up to 50, and replies `chain` entries `{nodeId, nodeTitle, via, inputs}` (a linked input as `<- Title.Pin`, else its default, object path or text; hidden pins such as a library call's self and `LatentInfo` are left out). A member step's batch result lists its node's pins (`FindBatchNode` when the step prepared no graph), and `RunPlacedStep` auto-places an `add_event` step with no `posX` as it does create steps.
- **Bare struct-member property names** — `McpResolvePropertyPath` backs `set_property`, `ResolveProperty`, `get_component_property`, `set_scs_property`, the SCS property bag and Blueprint `get`: a name not on the object resolves to the one by-value struct member of that name at any depth (reported as `propertyName`); several matches list the full paths. Collision keys, bare or `BodyInstance.`-prefixed, go through `SetCollisionProfileName`/`SetCollisionEnabled` on live components and SCS templates; a raw `BodyInstance` write recreates existing physics state (control_actor path). `ResolveNestedPropertyPath` misses append `similar:` (`McpSimilarPropertyNames`: up to 8 names sharing a 3+ letter word with the segment, rarer words ranking higher). After a write, `HandleSetObjectProperty` runs `McpPropertyActorAccess::RefreshMaterialHostAfterEdit`: an object whose outer chain holds a `UMaterial` or `UMaterialFunction` (an expression's own `PostEditChange` never reaches it) gets that host's `PreEditChange(nullptr)`/`PostEditChange()`, the pair `compile_material` runs, which rebuilds its cached expression data (the parameter lists instances read) and recompiles; the reply says `materialRebuilt`.
- **`find_text`** — `searchText` (required), `caseSensitive`, `limit` (default 50, 1-500), `packagePaths` (default `/Game`) and `includeLevel` (default true) match string/text/name properties (and an object or soft reference to another package by its path, never `/Script` classes) in Blueprint graph pins and comments, SCS templates, class defaults, widget trees, DataTable rows, String Table sources and the open level's actors and components (skipping `NetDriverName`, `BodyInstance`, `SpriteInfo`, `FolderPath`); replies `matches` (`asset`, `where`, `field`, `text`, `nodeId` for pins), `matchCount`, `scannedAssets`, `truncated`.
- **Widget authoring** — `McpAuthorWidgetAnimationKey` checks the track type and value shape (`KeyValueError`) and `McpAddWidgetAnimationTrack` the kind before any binding, track or section exists; track and key replies carry `widgetPath`, and `add_animation_track` answers `createdTrack`/`createdBinding` like the key. `set_size` on a HorizontalBox/VerticalBox child writes `sizeRule` (Auto or Fill) and `fillValue` through the slot's reflected `FSlateChildSize` (a lone `fillValue` means Fill, negative refused; neither is `MISSING_PARAMETER`; an unknown rule, or either field on a canvas child, `INVALID_ARGUMENT`); `duplicate_widget` copies a widget and its subtree under `newParent` (default the source's parent) with the slot layout, named `newName` or `<name>_Copy`, at `index` (default right after the source, or last under another parent), replying `slotName`, `newParent`, `index`, `copiedWidgets[]`; `reparent_widget` takes `index` (`ShiftChild`, clamped, so the same parent reorders). Adds refuse a taken `slotName` with `NAME_CONFLICT` and a free suggestion (`McpWidgetNameConflict`: designer rename rules, BindWidget properties allowed), an unnamed second add gets a free suffix, and a widget whose post-add compile fails is removed again.
- **`set_style` fields** — `hoverSoundPath`/`pressSoundPath` (Button slate sounds, empty clears), `justification` (left, center/centre, right), and on a text block (or a content widget whose child is one) `fontFamily`, `typeface` (checked against the composite font's faces), `letterSpacing` and `copyStyleFrom` (another text block's font, colour and shadow), applied before `fontSize`; unsupported targets are `STYLE_FIELD_UNSUPPORTED` and a RichTextBlock refuses the font fields.
- **Widget property bindings** — `bind_text`, `bind_color`, `bind_enabled`, `bind_visibility` and `bind_percent` write a real UMG binding: a compatible pure function binds directly (`SIGNATURE_MISMATCH` otherwise), a variable gets a generated `Get_<Widget>_<Property>` getter, and a binding that fails to compile is removed (`BINDING_INVALID`). The records declare `property`, `functionName`, `generatedGetter`, `bindings` and `saved`, so the native door returns them at top level.
- **`preview_widget` returns an image** — `McpDrawWidgetPreview` draws a transient `UUserWidget` (Designing and ExecutePreConstruct, so Construct graphs do not run) with `FWidgetRenderer` at the project's DPI scale for `resolution` WxH (default 1280x720, clamped 64-3840 x 64-2160) and replies `imageBase64`, `mimeType`, `width`, `height`, `sizeBytes`; the Widget Blueprint editor opens only with `openEditor` (default false). No assets are marked changed.
- **Asset referencers and multi-path `exists`** — `exists` takes `assetPaths` and answers `exists` (all present) plus `existsByPath`; `get_dependencies` with `referencers: true` answers from `IAssetRegistry::GetReferencers` under `referencers`; both lists are keyed by `FPackageName::ObjectPathToPackageName` (an object path resolves) and sorted with `FNameLexicalLess`.
- **Folder moves, Blueprint refresh, explicit renames** — moving or renaming with a content folder as `sourcePath` (`HandleMoveFolder`) renames every non-redirector asset in it, refuses PIE (`PIE_ACTIVE`) and moving into itself, parks the editor on `NewMap` when the open level is inside (`UNSAVED_CHANGES` if dirty), settles redirectors, deletes the source folder only if left empty and reloads the level (`reopenedLevel`, `levelNotReopened`). `refresh_blueprints` runs `RefreshAllNodes`, a diagnostic compile and a save for each Blueprint (Widget and Animation Blueprints included) in the selection (`refreshedCount`, `savedCount`, `compileErrors`; `NO_BLUEPRINTS`, `COMPILE_FAILED`). `bulk_rename` takes `renames` [{`sourcePath`, `newName`}]: a missing source or taken destination is skipped into `skipped[]`, `assetPaths`/`folderPath` are used only when `renames` produced nothing, and a failure lists `notRenamed`.
- **Targeted save and unsaved state** — `control_editor.save_all` takes `assetPaths`: only matching dirty packages are saved, the rest counted in `leftDirtyCount` (always present, 0 without `assetPaths`). `get_summary` (loaded branch) and `get_current_level` return `unsaved`, `unsavedPackages` (first 100 blocking dirty world/content packages) and `unsavedPackageCount` (`AddUnsavedState`), also true for a dirty loaded external-object package (World Partition actors); their `actorCount` is `Algo::CountIf(Level->Actors, IsValid)`, where `Actors.Num()` also counted the null slots reinstancing leaves.
- **Output files** — `list_output_files` and `delete_output_file` work only under `Saved/Screenshots`, `Saved/unreal-mcp`, `tmp/unreal-mcp` and `temp/unreal-mcp`. List: newest first (path tie-break), `limit` (default 100, clamped 1-500), `offset`, `root` (else `INVALID_ARGUMENT`), `extension`; replies `files`, `total`, `returned`, `offset`, `hasMore`, `nextOffset`, `roots`. Delete: `path` or `paths[]` (`results`, `deletedCount`, `failedCount`, `PARTIAL_DELETE`), refused for `..`, drive letters or a leading `/` and re-checked against the roots (`PATH_OUTSIDE_OUTPUT_ROOTS`); replies `changedEntities`.
- **Screenshot options** — `keepFile` (default true) on `control_editor.screenshot` and the ui game-viewport capture: false skips the file save (`INVALID_ARGUMENT` without `returnBase64`), and `path`/`screenshotPath` are set only for a saved file (`saved`). The editor-viewport mode applies `location`/`rotation` to the level viewport first (`cameraLocation`/`cameraRotation`; under PIE they move the ejected view, `view` says which view was photographed (`editor_viewport`, `pie_game`, `pie_ejected`), and a player who is not ejected gets `PIE_VIEW_NOT_EJECTED`). An ejected player no longer feeds the game viewport, so `game_viewport` (here and in the ui capture) takes the editor viewport that draws the play world. A resampled `game_viewport` or `full_editor_window` capture also returns the source frame's `viewportWidth`/`viewportHeight`. The `window` parameter of both screenshot records is `["integer", "string"]` (the handler already read a numeric `window`; the record refused it before the plugin saw it). Shader state: `McpShaderJobsRemaining` (`GShaderCompilingManager->GetNumRemainingJobs()`, 0 without a manager) feeds `McpAddShaderCompileState`, which every capture reply (`SendScreenshotReceiptForMcp`, the ui game-viewport capture) and the five `inspect` editor-state reads (`HandleInspectSettingsAction`) call: `shadersCompiling`, plus a warning appended to the reply's own `warnings` while jobs are left. `waitForShaders` goes through `McpDeferForShaderCompile`, which `HandleControlEditorScreenshot` calls before it picks a mode: it polls on the core ticker (every 0.25 s, at most `McpShaderWaitMaxSeconds` = 25 s, under the bridge client's 30 s) and resumes the same handler with `shaderWait` {`waitedSeconds`, `jobsLeft`, `timedOut`} in the payload, so the game thread keeps running and the compiling can finish.
- **`control_editor.restart_editor` `relaunch: false`** — schedules `GEditor->CloseEditor()` instead of `RestartEditor`, behind the same unsaved-package gate; reply `closing: true`, `restarting: false`.
- **`read_log` filter alternatives** — `filter` splits on `|` and matches a line containing any part, case-insensitively; the buffered read also matches the category. `PreviousRunLogPath` lists only `<log base name>-backup-*.log` (`FPlatformOutputDevices::GetAbsoluteLog`): `*-backup-*.log` also matched the Fab browser's `cef3-backup-*.log`.
- **`stop_sound`** — `play_sound_2d` now spawns with `UGameplayStatics::SpawnSound2D` and keeps the component in a weak list (`McpPreviewSounds`); `stop_sound` stops those (only `soundPath`'s when set, `ASSET_NOT_FOUND` for an unknown path) and, with `all`, calls `StopAllSounds(true)` on every world context's audio device (`stopped`, `allStopped`); `soundOp` `pause`/`resume` (`pause_sound`/`resume_sound`) call `UAudioComponent::SetPaused` on the same components (with `all`, every playing `UAudioComponent` found by `TObjectIterator`), counting only those whose state changes (`paused`, `resumed`).
- **Audio sections carry a sound** — `add_section` `soundPath` on a `UMovieSceneAudioTrack` (`Sequence/McpAutomationBridge_SequenceHandlersSections.cpp`) sanitizes the path (`MapContentRootInline`, `SanitizeProjectRelativePath`; `INVALID_PATH`), builds the section with `AddNewSoundOnRow` (one second for a zero-length sound), re-places it with `InitialPlacementOnRow` when an explicit `end` changes its length so it never overlaps a section on its row, and replies `soundPath`/`soundName`.
- **MetaSound graph edits and reader** — `remove_metasound_node` (`nodeId`/`nodeIds`, all-or-nothing; graph I/O nodes are `NODE_NOT_REMOVABLE`), `disconnect_metasound_nodes` (one input link or every link out of a source output; `PIN_NOT_FOUND`, `NOT_CONNECTED`, `LINK_MISMATCH`, `DISCONNECT_FAILED`) and `get_metasound_graph` (nodes with class, kind and input literals, edges by node and pin name, counts, root `graphInputs`/`graphOutputs`, all pages). `build_metasound` steps gain `remove_node` and `disconnect` and resolve `$id` inside `nodeIds`. UE 5.5+ (`MCP_HAS_METASOUND_FRONTEND_V2`), else `METASOUND_FRONTEND_NOT_SUPPORTED`.
- **Nav modifiers on placed actors** — `create_nav_modifier` without `blueprintPath` spawns an `ANavModifierVolume` (`location`, `extent` default 200,200,100 and positive, `actorName`; an unknown `areaClass` is `INVALID_AREA_CLASS`); `create_nav_modifier_component` with `actorName` and no `blueprintPath` adds an instance `UNavModifierComponent` to the placed actor. Both required `blueprintPath` before.
- **Find by mesh and by material** — `find_by_mesh` and `find_by_material` (`control_actor` `find` `findBy` `mesh`/`material`; `Domains/ControlActor/Find/McpAutomationBridge_FindByAsset.cpp`, `McpFindByAsset::HandleFindByMesh`/`HandleFindByMaterial`, dispatched from `ControlActorDispatch.cpp`) scan the Play In Editor world while a session runs, else the editor world, and answer `actors` (`label`, `name`, `path`, `class`, `components`) and `count` as the other finds do. A mesh matches a `UStaticMeshComponent` whose `GetStaticMesh()` is the loaded `meshPath` (`McpLoadAsset`; instanced and foliage components say their `instances`); a material matches a `UPrimitiveComponent` slot whose `GetMaterial(i)` (the override, else the mesh default) is the loaded `materialPath` (`LoadMaterialForMcp`), unwrapping `UMaterialInstanceDynamic::Parent`, and lists the matching `slots`. `limit` (default 200, clamped 1-1000) cuts the list and replies `truncated` and `totalCount`; an unloadable path is `MESH_NOT_FOUND`/`MATERIAL_NOT_FOUND`, a missing one `INVALID_ARGUMENT`.
- **Blueprint default writes** — `HandleSetObjectProperty` on a CDO target sets the declared variable's `DefaultValue` text from the written object (`McpPropertyTarget::KeepDeclaredDefault`; the first segment of a dotted path), since every compile writes that text back into the new CDO; after `CompileBlueprint`, `FindOnCurrentDefault` finds the property again on `GeneratedClass->GetDefaultObject()`, and the reply, `value`, `AddVerification`, the owning package (the Blueprint's, so the save runs) and a `watch` on the written object follow the new object. The property's export text before and after the compile must match (skipped for instanced references), else `PROPERTY_SET_FAILED`. `ResolvePropertyTarget` re-points a `Default__` CDO of a replaced class (`REINST_`, `SKEL_`) to the Blueprint's current default object, and `IsSupersededTarget` (a `REINST_`/`SKEL_`/`TRASHCLASS_` or `CLASS_NewerVersionExists` class, or a Blueprint object in the transient package with no `GEditor->PlayWorld`) refuses a write with `STALE_TARGET` before `Modify()`; the handler used to reply against the replaced object, so each call landed on the next `REINST_..._N` with `saved: false`.

## [0.6.0-beta-b] - 2026-09-25

Plugin-side changes since the `v0.6.0-beta-a` tag, from the code diff. The server-side view is in the root `CHANGELOG.md`.

### Added
- **In-process batches** — `FMcpResponseCaptureRegistry` (`Core/Requests/`) lets a handler run other handlers under a synthetic request id and read their replies as data: `SendAutomationResponse` checks it first and never delivers a captured reply. `build_graph` (`Domains/BlueprintGraph/...Batch*.cpp`), `build_material_graph` (`MaterialAuthoringGraphBatch.cpp`), `build_metasound`, `spawn_batch` (`ControlActorSpawnBatch.cpp`) and the list forms of `set_transform`, `set_blueprint_variables`, `set_material`, `add_tag`, `delete_by_tag`, `remove_scs_component` and `set_variable_metadata` are built on it, so every item keeps its single-call checks. A `build_graph` batch resolves every function and variable it names before running any step (`ResolveGraphCallFunction` is shared with node creation).
- **`FMcpLogHistory`** (`Domains/Log/`) keeps the recent editor log in memory from subsystem start; `read_log` serves it, or the UnrealBuildTool log, the Live Coding console log, or an earlier run's backup log (`runsBack`), and every returned line passes the response sanitizer.
- **`launch_build`** (`SystemControlHandlersLaunchBuild.cpp`) starts the packaged Win64 game from inside the project for a timed smoke run on an `FTSTicker`, and `package_status` reports its maps, errors and log tail.
- **PIE game control** — Enhanced Input injection with holds in game seconds, `key_tap` held for at least two frames, `widget_list` / `widget_click` over the live UMG tree (`ControlEditorWidgetInput.cpp`), `set_fixed_delta_time` through `FApp` (reset on `EndPIE`), multi-frame `step_frame`, `restore_editor_window` (restores the root window through its placement without activating it and turns off the background throttle), and `restart_editor`.
- **MetaHuman Creator** handlers (`Domains/MetaHuman/`), Sequencer `list_track_keys` / `remove_keyframe`, `skin_mesh_to_skeleton` (GeometryScripting, 5.5+), IK Rig and retarget pipeline construction (`AnimationRetargetPipeline.h`, IK Rig 5.6+, batch retarget 5.8), transition-rule conditions and `delete_transition`, and Fab driven by reflection (`McpFabDirectApi.cpp`, browser widget reuse, listing claims).
- **`McpSafeOperations::McpDeleteAssetAndFile`** (`Safety/McpSafeOperationsAssetDelete.h`) finishes a delete the engine left half done: it unloads the leftover package and removes the `.uasset` only once the package is really gone, and is true only when the file is.

### Changed
- **Native requests** are timed from their last progress: a live game thread sends a "still working" progress every 20 s, `MaxLifetimeSeconds` still ends a request that never answers, and progress never goes backwards (`MCP/Transport/`).
- **Native gateway** — an omitted fold selector is inferred from the parameters sent (`McpInferFoldSelector`, mirroring `inferSelector`), native `search` honours `effect` and `tool`, batch items take `{x,y,z}` vectors like the single form, `RESULT_TOO_LARGE` names the capability's own narrowing parameters, and a world edit during PIE gets a receipt warning.
- **Replies that report what happened** — dozens of handlers read their result back before answering, including the GAS mutations (#606: compile, verify on the compiled class, then save), SCS template edits that now reach placed instances, material and MetaSound parameter writes, asset delete and duplicate, `set_property`, `set_project_setting` and `set_preferences`.
- The GAS verification handlers live in `Domains/GAS/Authoring/` (the GAS folder is at the 25-file limit), and the AI domain creates its assets through one `CreateAIAssetInPackage`.
- The integer `Version` in `McpAutomationBridge.uplugin` follows the semver (`600` for 0.6.0).

### Removed
- `add_control`, `add_rig_unit` and `connect_rig_elements` (unpublished, `NOT_SUPPORTED` on every path), the always-true `SubAction` wrappers, the response send "retry" loop that never retried, and the unused `bAllowLoopbackMediaUrls` / `AllowedLoopbackMediaUrlPrefix` settings.

### Security
- Console commands whose first token is `debug`, `exec` or one of the engine crash, stall and hitch commands are refused (`DANGEROUS_ENGINE_COMMAND`) by the generated console policy.
- Identity keys (`UserId`, `AccountId`, `LoginId`) are redacted from log lines and errors; `console_command` output, `read_log` lines and the `launch_build` log tail pass the per-line sanitizer.
- The path canonicalizer admits plugin content roots and still refuses host filesystem roots; `launch_build` only runs a game inside the project; batch steps cannot leave the batch's asset, and actor list forms stop at 500 items.

## [0.6.0-beta-a] - 2026-09-18

### Added
- **Content ingestion — `manage_asset.list_content_sources` and `manage_asset.migrate_assets`.** Reusable content already on the machine was unreachable through the gateway: `asset.import` runs source-file importers and refuses any path outside the project directory, so an installed engine template or a Quixel Bridge / Fab pack could not be brought in at all. Bridge and Fab deliver cooked `.uasset` packs rather than source art, so ingestion is a package copy plus an asset-registry scan — the same operation that pulls in a template, which is why these are generic rather than Megascans-specific. `list_content_sources` enumerates engine templates, engine/plugin content, and downloaded Bridge packs; `migrate_assets` copies a tree into `/Game` with `dryRun` preview and a `maxPackages` cap. A migrate request never carries a filesystem path — it carries a root token (`engineTemplates`, `engineFeaturePacks`, `engineContent`, `enginePlugins`, `megascansLibrary`, `projectContent`, `projectPlugins`) plus a relative id, both resolved in `McpAutomationBridge_AssetWorkflowContentSourceRoots.h`, so no directory outside those roots is reachable. `destinationPath` defaults to `/Game` because reproducing the source layout is the only arrangement that keeps the `/Game/...` references stored inside the copied packages resolvable; anything deeper reports `referenceIntegrity: "at-risk"`.
- **Plugin management — `system_control.list_plugins`, `enable_plugin`, `disable_plugin`.** Migrated content usually depends on a plugin that is installed but disabled (ChaosVehicles for the advanced vehicle template), and without this the assets copy in and then fail to load their classes, which reads as a broken migration rather than a disabled module. Writes go through `IProjectManager::SetPluginEnabled` + `SaveCurrentProjectToDisk`; the response reports `restartRequired: true` because modules and content mount only at startup.
- **Native gateway surface** — the plugin's `/mcp` transport now exposes a single `unreal` tool with `search`, `describe`, `execute`, and `configure` operations, implemented by new `Private/MCP/{Gateway,Routing,Execute,Primitives,Resources,DynamicTools}/` modules.
- **Generated contract shards** — `Private/MCP/Generated/` and `Private/MCP/Tools/McpGeneratedParentRegistry*` are emitted from the TypeScript capability records by `npm run registry:generate`. They are committed but must never be hand-edited.
- **Native MCP protocol primitives** — `Private/MCP/Primitives/` adds the MCP Tasks surface (`McpTaskMethods`, `McpTaskStore`) for `2025-11-25`, a subscription store with a notification coalescer so bursts of editor changes collapse into one client notification, resource revision stamps, completion pools and provider, prompt catalog/render/argument validation, a client profile store and session capability profile, and an elicitation decision policy. The elicitation policy is metadata/decision only — no transport wiring, no server-initiated RPC, no new MCP method — and never marks a secret, token, credential, or destructive-confirmation value as safe to elicit. Cross-transport parity with the TypeScript primitives is audited by `npm run primitives:check`.
- **Protocol negotiation** — `McpSupportedProtocolVersions` accepts `2025-11-25` (latest), `2025-06-18`, and `2025-03-26`. `initialize` echoes the highest mutually supported version, or the latest for an unknown well-formed request; `McpDefaultProtocolVersion()` (`2025-03-26`) backs post-initialize requests that omit the `MCP-Protocol-Version` header.
- **Capability authorization primitives** — `Private/Foundation/McpCapabilityPrincipal`, `McpCapabilityAuthorization`, and `McpCapabilityPathScan` give the plugin its own authorization identity instead of trusting the caller's claim.
- **Idempotency ledger and compensation receipts** — `Private/Foundation/McpIdempotencyLedger` (cap 4096, mirroring the TypeScript ledger's cap of 1024) and `McpCompensationReceipt`.
- **`MCP_NATIVE_PORT` environment variable** — overrides the native MCP HTTP/SSE port (`NativeMCPPort`) at startup without editing committed ini, so a project can run several editors at once on distinct ports. Mirrors the existing `MCP_MAX_*` env overrides; falls back to the `Native MCP Port` project setting when unset or invalid.
- **`IKRigEditor` optional module** — declared for the `create_ik_rig` path so IK Rig creation does not require a hard dependency on the editor module.
- **Component-bound events in `add_event`** — pass `componentName` plus `eventName` (the delegate name) to wire a component's multicast delegate to a `UK2Node_ComponentBoundEvent` with `ComponentPropertyName`, `DelegatePropertyName`, and `DelegateOwnerClass` set. Idempotent on repeat calls; guarded by `MCP_HAS_K2NODE_COMPONENTBOUNDEVENT`.
- **Typed class pins in `create_node` / `add_node`** — dedicated branches assign `UK2Node_DynamicCast::TargetType` and `UK2Node_CreateWidget::WidgetType` from a `targetClass` payload, so casts and CreateWidget nodes come back typed instead of as wildcard/"Bad cast" nodes. Shared `ResolveTargetClassFromString` / `ReadTargetClassPayload` helpers accept the same input forms and legacy field fallbacks across every branch with a class pin.
- **18 widget-authoring actions added to the native `WidgetAuthoring()` routing array** — `add_quest_tracker`, `add_safe_zone`, `add_spacer`, `add_widget_component`, `add_widget_switcher`, `bind_localized_text`, `create_credits_screen`, `create_shop_ui`, `create_widget_style`, `delete_animation`, `get_widget_slot_info`, `remove_widget`, `rename_widget`, `reparent_widget`, `set_font`, `set_localization_key`, `set_margin`, `set_widget_binding`. The handlers existed but were unreachable because the action names were absent from the routing array; the TypeScript `WIDGET_AUTHORING_ACTIONS` set gained the same 18.
- Native cinematics, Movie Render Queue, media, Take Recorder, and replay automation with direct `/mcp`, WebSocket, and live-editor verification coverage.
- **Folded capability families on the native surface** — the native registry serves the same 377 folded records as the TypeScript surface: `McpNativeGatewayFolding` applies the folded pins before defaults and schema validation and resolves the dispatch action after them, `FindByParentAction` falls back to any legacy pair so every former `{tool, action}` name still resolves, and the native completion pool completes the old names. `describe` advertises each family once, with its selector.
- **Pre-queue capability gate** (`Core/Security/McpPrequeueGate`) — every request is authorized before it reaches the editor queue. The gate resolves its demand with the same `McpHandlerUtils::NormalizeAction` the dispatchers call, so the gate and the dispatcher cannot disagree about which capability a request needs.
- **Scoped capability tokens** — a scoped token carries its profile, scopes, allowed path prefixes, allowed projects and per-minute request/tool-call quotas, and the `bridge_ack` authority block reports the effective identity.
- **Principal-keyed quota ledger** (`McpPrincipalQuota`) — bounded to 256 tracked identities with least-recently-seen eviction, charged only after every other refusal, answering `QUOTA_EXCEEDED` as retryable.
- **Single-use consent nonces** — a consent grant is consumed by the request that used it; a replayed grant answers `CONSENT_REUSED`.
- **Typed refusals for stalls, state and addressability** — `EDITOR_BLOCKED` (game-thread stall over 15 s), `EDITOR_STATE_MISMATCH`, `STALE_STATE`, the `UNDO_UNAVAILABLE_*` family, and `OBJECT_NOT_ADDRESSABLE` from `McpSafeReflectionTarget`, which denies a reflected write to a target the principal cannot address so a `write`-scoped principal cannot reach `bRequireCapabilityToken` through `inspect.set_property`.
- **Bounded native sessions** — at most 16 active sessions with a 120 s idle reclaim, and a 32-connection ceiling that answers 503 beyond it.
- **User-defined action aliases** — a project can add action names in `handler-aliases.json` (schema `Resources/MCP/custom-handler-aliases.schema.json`, tests `Tests/McpCustomHandlerAliasTests.cpp`): version 1, at most 128 aliases and 64 KB, `lower_snake_case` only, resolved through three search paths; an alias pointing at another alias or at the protected `inspect`/`manage_tools` actions is rejected, and an alias whose target is not registered yet stays pending until it is.
- **Promoted skeleton routes** — the fifteen previously hidden skeleton routes (twelve promoted to canonical records, the three `delete_*` spellings still hidden) now carry explicit names on the native `Skeleton()` routing array.
- **Word-level native search with paging** — the native gateway search matcher scores word-level matches and accepts `actionOffset` and `maxBytes`, so a large action list can be paged.
- **Fab adapter module** — `McpAutomationBridgeFab` bridges the Fab asset store through the Fab plugin's own browser widget and download API (`McpFabBrowserBridge`, `McpFabSearchOperation`, `McpFabDetailsOperation`, `McpFabAddToProject`, `McpFabImportWatcher`). Its Fab and Megascans engine dependencies are declared optional and listed in `PublicDelayLoadDLLs` on Win64, so the module compiles away when they are absent; the store actions themselves are dispatched by `Domains/AssetWorkflow/`.
- **Diagnostics snapshot store** — `Foundation/Diagnostics/` records request admission, refusal, terminal, handshake and session events to `<Project>/Saved/MCP/diagnostics/`, with atomic temp+rename writes, previous-session rotation, and corrupt-file tolerance.

### Security
- Scopes are exact-set membership with an `Admin` wildcard, not rank-based — `Write` does not imply `Read`, and an unresolvable capability demands `Admin`.
- Consent arrives as an `automation_request` envelope sibling and is re-validated plugin-side; it is never inferred from loopback, a prior call, idempotency, or preview.
- Capability tokens compare in constant time and are never logged; the plugin re-enforces every check the TypeScript layer performs.
- Added continuous local output-path validation, disabled network-backed media URLs because redirect destinations cannot be pinned, added client-scoped native rate limits that survive session rotation, enforced strict native `manage_tools` argument validation, and sanitized streamed log payloads.
- **`action` and `subAction` can no longer disagree.** `AuthorizeAutomationRequest` normalizes any `automation_request` payload that declares both with different values (overwriting `action` from the authoritative `subAction`), and the native execute stage stamps `subAction` from the server-resolved action, so a client can neither lower its own scope nor raise what runs past what was authorized.
- **Capability-token auth is on by default** (`bRequireCapabilityToken`), the token is generated per install at `<ProjectRoot>/Saved/MCP/capability-token`, and both transports compare it with `McpConstantTimeTokenEquals` (`Foundation/McpSecureTokenCompare.h`) so comparison time never leaks how much of a token matched.
- **URL-looking arguments are refused** in handler validation, including loopback and `file:` URLs, rather than trying to allow a safe subset.
- **Scoped tokens are narrower than the legacy token by construction** — a scoped token may list only `Read`/`Write`/`Destructive` (never `Admin`), and a scoped token colliding with the legacy token wins because the narrower grant applies.

Header selection now probes with `__has_include` instead of hard-coded version numbers wherever the engine moved a header, and the remaining guards were corrected against the engine source. Affected areas: the StructUtils headers (`MCP_USER_DEFINED_STRUCT_HEADER`, `MCP_INSTANCED_STRUCT_HEADER`), `FAssetCompilingManager::FinishCompilationForObjects`, `UWidgetBlueprint::WidgetVariableNameToGuidMap`, `CreateNewIKRigAsset`, `FString::RightChopInline`/`LeftInline`, and `PhysicsEngine/SkeletalBodySetup.h`. - **Render console handler** — use `FJsonObject::HasField()` instead of `Values.Contains(FString)`, following the `FJsonObject::Values` key-type change.
- **Asset soft-path fallback returned the wrong string shape** — `MCP_ASSET_DATA_GET_SOFT_PATH` used `PackageName` (`/Game/Foo`) where callers expected an object path (`/Game/Foo.Foo`). It now uses `FAssetData::ObjectPath`, the equivalent of the `GetSoftObjectPath()` used in the other branch.
- **`validate_niagara_system` now reports real errors** — previously hard-coded `isValid=true`; it now builds a full Niagara system view model and harvests stack issues (e.g. "The module has unmet dependencies.") across the system and emitter stacks. A data-processing-only view model can't be used because `UNiagaraStackModuleItem::RefreshIssues()` emits no per-module issues in that mode.
- **IK Rigs created on the `NewObject` fallback path are registered with the asset registry** — `FAssetRegistryModule::AssetCreated()` is now called explicitly on that branch, which the static factory does for us on engines that have it. Without it the rig existed on disk but was unregistered, so it never appeared in the Content Browser until an unrelated rescan happened to pick it up: the asset looked lost even though creation had reported success.
- **Widget GUID registration logs a truthful no-op** — `RegisterWidgetGuid`, `UnregisterWidgetGuid`, and `RegisterAnimationGuid` each logged "registered"/"unregistered" on engine versions that have no `WidgetVariableNameToGuidMap`, claiming work they had not done. On those versions the engine owns the widget variable's GUID in `UBlueprint::NewVariables[].VarGuid`, and writing our own would overwrite a value existing bindings resolve through — so a no-op is correct, it just has to say so. `RegisterAnimationGuid` still adds the animation to `WidgetBP->Animations`, which is the part that matters there.
- **Bare `remove_variable` / `rename_variable` now match on the native transport** — the Blueprint variable removal/rename handler matched only the `blueprint_`-prefixed forms, so the bare action names fell through unhandled. Both the snake_case (`remove_variable`, `rename_variable`) and alphanumeric-lowered (`removevariable`, `renamevariable`) bare forms are now accepted alongside the prefixed ones.
- **Every texture call was failing** — `action` is injected by the consolidated routing layer (`WithPayloadSubAction`) as the legacy dispatch verb, but it is not a client parameter and was absent from the handlers' `ValidParams` allowlists, so schema-valid texture calls were rejected with `TEXTURE_ERROR: Invalid parameter: action`. Added to all five affected handlers (gradient, noise, normal, pattern, resize).
- **`add_variable` now applies `defaultValue`** — the handler read the payload field but never assigned it, so every variable was created with a zero/empty default. The parsed default is written to `FBPVariableDescription::DefaultValue` with type-aware formatting (booleans lowercased, integer/byte categories as whole numbers, floats via `SanitizeFloat`, strings and struct literals passed through).
- **`ListenPorts` drop warning** — when multi-listen is on and a partial `ListenPorts` override omits a default bridge port (8090/8091), a warning is logged instead of the drop being silent (the user's ports stay authoritative).
- **Clean build fixed** — the memreport scan passed `256` as a seventh argument to `IFileManager::FindFilesRecursive`, but that parameter is `bClearFileNames`, not a result ceiling, so the call did not compile. The bound was dropped rather than reworked: truncating is also wrong here, since picking the newest of an arbitrary subset can miss the actual newest report. A real traversal bound would need `IterateDirectoryStatRecursively`, which can stop early and read `ModificationTime` in the same pass.
- **Last source warning cleared** — `FLinearColor ColorValue;` left its channels uninitialized in the cinematics material-parameter track handler, and the only writer runs on one branch, so the compiler could not correlate the write with the guarded use and warned C4701. Seeded to opaque black, matching `ReadLinearColor`'s own defaults.
- Wait for actual replay seek completion, keep render ownership until executor settlement, roll back Take Recorder panel/source state after asynchronous failures, reject invalid render limits before queue mutation, and verify tokenized render filenames.
- **Compatibility sweep beyond the earlier fix** — the `MCP_HAS_IKRETARGETER_SET_IKRIG_ENUM` boundary was reversed because the minor it named sat on the wrong side, and three shims were added for APIs that differ across the supported range (`MCP_SET_ENUMS`, `MCP_HAS_GET_OBJECTS_FLAGS`/`MCP_GET_OBJECTS_NO_NESTED`, `MCP_DISALLOW_SHRINKING`).
